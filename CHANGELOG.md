## Community Testing

Version 1.0 is intentionally frozen as the first public testing baseline.

Changes should not be made directly to the canonical version without documented justification.

Testing should follow:

- `TESTING_PROTOCOL.md`
- `CONTRIBUTING.md`

## Known Questions

The public alpha is specifically intended to test:

- whether the system over-researches simple questions
- whether it under-researches complex questions
- how well it transfers across domains
- how well it transfers across AI models
- whether the research-depth selection works reliably
- whether the full protocol is unnecessarily long in some situations
- whether specific instructions are redundant
- whether some stages conflict
- whether novice users can use it naturally
- whether expert users identify important omissions
- whether the system challenges false premises reliably
- whether source-lineage checks are practical across domains
- whether proposed simplifications preserve research quality
- whether modifications introduce regressions

# CHANGE STANDARD

A canonical change should have a documented reason.

Whenever possible, future release notes should explain:

- what problem was observed
- what evidence supported the change
- what changed
- what testing was performed
- what regressions were checked
- what remains uncertain

The goal is not to maximize the number of changes.

The goal is to preserve a trustworthy history of how the Research Pass evolves.
