Candidate B — Execution & Output Contract

Status: EXPERIMENTAL CANDIDATE
Canonical status: NOT CANONICAL
Based on: Universal Research Pass v1.0 frozen public-alpha baseline

Purpose

Candidate B tests whether the Research Pass can reduce unnecessary visible output without sacrificing materially useful research.

It is built from:

community feedback about over-expansion and execution cost

a reproducible fixed-evidence case where canonical v1.0 continued generating after reaching the core evidentiary judgment

real Creator OS field cases showing the opposite risk: important boundary conditions and system refinements sometimes appear after the primary verdict is already available

The experimental target is therefore not:

answer first and stop

It is:

surface the answer early, then continue only while additional research or explanation earns its cost.

What Changed

Candidate B adds one experimental execution/output contract.

1. Research Stop ≠ Output Stop

It separates:

Is more investigation likely to change or qualify the answer?

from:

Is more visible explanation likely to help the user?

2. Surface the Answer Early

The useful conclusion should normally appear before optional research machinery.

This is an output-order rule, not permission to terminate research prematurely.

3. Post-Decision Value Gate

After the answer becomes decision-sufficient, additional visible analysis should normally justify itself by materially changing or qualifying:

the answer

confidence

rival adjudication

failure conditions

implementation

uncertainty

auditability

4. No Report-Completion Obligation

Research Pass headings are tools, not quotas.

A section should not appear merely because the template contains it.

5. Output Proportionality

Visible detail should scale with complexity, stakes, uncertainty, disagreement, and auditability—not with the number of internal steps performed.

6. Auditability Protection

Compression must not remove evidence needed to evaluate consequential conclusions.

Why Candidate B Exists

Field evidence from Magic's real Creator OS showed two things at once:

Problem

The system often reaches a decision early and continues through a large report structure.

Counter-risk

Some later material genuinely improves the result.

Examples included:

rejecting fixed WIP doctrine

rejecting fixed slack percentages

preserving recovery without inventing a recovery prescription

separating reply-video candidacy from the response action set

treating pin/highlight as a curation overlay

treating recurring commenter history as context rather than priority authority

rejecting playlists as generic algorithm hacks

distinguishing legacy-content existence from homepage prominence

So Candidate B is deliberately designed to avoid optimizing for brevity at the expense of useful qualification.

Related Hypotheses

Candidate B is most relevant to:

H001 — Over-research on simple questions

H009 — Research Pass value may come primarily from doctrine rather than prose volume

H012 — Research doctrine and execution architecture should be separated

H013 — Modern model capabilities may make parts of explicit Research Pass scaffolding redundant

Candidate B may justify a new narrower hypothesis if testing repeatedly shows that output-contract pressure is a distinct failure mode from research-depth selection.

What Candidate B Does NOT Test

Do not interpret Candidate B as a test of:

modular skill architecture

multi-agent execution

cross-vendor agents

cheaper model routing

indexed retrieval

glossary normalization

instruction deduplication

Candidate A's capability-honesty patch

Brian's broader modular-control architecture

Those remain separate experimental variables.
